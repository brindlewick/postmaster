# Run record: 2026-09-26, `postmaster`, #36, the review rounds

The review of pull request #39, which implemented #36, run by hand in five rounds. It is the first
evidence for [when a review loop should stop](../concepts/review-convergence.md). It was not a
postmaster dispatch: there is no ledger, run log, card or harness stream, only each reviewer's
report, the briefs, and the implementing session's own index
[@runs/2026-09-26-postmaster-36/promotion.md].

## The run

- Target: `postmaster`.
- Ticket: #36, run the style, bug and security reviews as one loop. Pull request #39.
- Reviewers: round 0, one general reviewer against the ticket's criteria; round 1, `/code-review`
  on the implementing session's model, with ten finder angles, a gap sweep and a verifier for each
  candidate; rounds 2 to 4, the bug and the security lens, each on model A and on model B, both
  from one vendor [@runs/2026-09-26-postmaster-36/README.md].
- Coachman: the implementing session. It wrote the fixes and the briefs, verified the findings and
  chose their dispositions [@runs/2026-09-26-postmaster-36/promotion.md].
- Outcome: merged on 2026-09-26 as `547687c` after round 4 [@runs/2026-09-26-postmaster-36/commits.txt].
  The class of defect the loop stopped on was filed as #57 and the remaining small checks as #58.

## Review findings, rounds 2 to 4

One row per distinct finding. A finding that two reports describe is one row, and the row names
every report that made it, with its own label and the severity it gave. `a` and `b` are model A
and model B [@runs/2026-09-26-postmaster-36/reports]. The disposition is the next round's brief,
by item number, or the ticket it was filed in [@runs/2026-09-26-postmaster-36/briefs].

Where each finding sat was worked out by running `git blame` on its cited lines at the snapshot the
round reviewed, and reading the result against the previous round's fix commit and against main.
A fix's number is its item in the brief of the round that checked it, which lists the previous
round's fixes: round 2's brief lists round 1's 21, round 3's lists round 2's 22, and round 4's
lists round 3's 10 [@runs/2026-09-26-postmaster-36/briefs].

- **made by fix *n***: the previous round's fix *n* created it;
- **left by fix *n***: it predates the previous round's fix *n*, which was meant to close it or its
  kind and did not;
- **earlier in the change**: the pull request introduced it before the previous round's fix;
- **on main**: it was on main before the pull request; **the merge**: it came with merging main.

Three are judgement calls: 2.08 could be read as left by fix 2, 2.18 sits in guards from two
commits, and 4.06 is partly on main. "Prose" is a runbook, its shell blocks included.
"(class)" marks what the postmaster does with a leg whose process exited without finishing, the
class the loop stopped on, as the implementing session named it
[@runs/2026-09-26-postmaster-36/README.md].

## Corroboration (bears on H2)

A finding is corroborated here when both models made it in the same round, each in its own
scratch. That happened 4 times in 48: 3.01, 3.03, 3.07 and 4.01. All 4 held up, meaning the
coachman accepted them rather than dismissing them. Of the 44 findings only one model made, 42 held
up; 2.14 and 3.09 were dismissed [@runs/2026-09-26-postmaster-36/reports]
[@runs/2026-09-26-postmaster-36/briefs]. The two rates do not separate. Five more findings were
made twice by one model under two lenses (2.01, 3.02, 3.05, 4.04 and 4.05), which is a model
agreeing with itself, not corroboration.

"Held up" is weaker here than H2 asks for: the coachman that judged it was the same vendor's
model, and nothing reviewed had run, so no fix was checked through a gate.

## Fixes re-reviewed by the other lens (bears on the review loop)

In round 3, three findings sat in a fix for a finding one lens had made, and only the other lens
found them: 3.06 (P3) and 3.08 (P1), found by the bug lens in fixes for security findings, and 3.10
(P2), found by the security lens in a fix for a bug finding. In round 4 there were none
[@runs/2026-09-26-postmaster-36/reports] [@runs/2026-09-26-postmaster-36/briefs]. These are the
catches that a sequence of lens passes could not make, since no bug reviewer saw a security fix.
