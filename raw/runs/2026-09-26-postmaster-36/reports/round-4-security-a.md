### 2. Findings

**A. P2. An env file that fails to source is not a refusal, and the poll resumes it forever.** `scripts/launch.sh:324` `if [ -n "${ENV_FILE:-}" ]; then set -a; . "$ENV_FILE"; set +a; fi`, under `:31` `set -uo pipefail`, then `:325` `exec "${cmd[@]}"`. Verified by execution with a stub harness:
- `X=$UNSET_VAR` in the file: exit 1, nothing launched, `.err` first line `…/unbound.env: line 1: UNSET_VARIABLE_ZZ: unbound variable`.
- `PATH=/some/dir` without `$PATH`: exit 127, nothing launched, `.err` `scripts/launch.sh: line 325: exec: claude: not found`.
- `exit 0` in the file: exit 0, nothing launched, empty `.err`, empty stream.
None opens with `launch:`. For a leg that already has a thread id (every resume: rulings, remounts, the merge word, and the takeover launch while `coachman.legs.<n>` still names the walled thread), `postmaster.md:181-183` classifies it as "a spent thread: remount it by resuming", every poll, and step 5 overwrites the `.err` each time. `INSPECT` never fires because the resume prompt files and log lines keep changing. Stage B pre-flight (`postmaster.md:84-88`) runs only `form`, which exits before line 324, so all four broken files pass pre-flight (shown). Exploit path: the user's own env file, through an ordinary mistake (an unset `$VAR` in the postmaster's environment, a `PATH=` meant as a prepend, or an `exit` guard); what results is a run that churns `resume` lines indefinitely instead of stopping and asking. Confidence high. A subshell probe of the env file before `form` and `launch` exit, and a `command -v "${cmd[0]}"` after sourcing, would turn all three into `launch:` refusals.

**B. P3. A syntax error in the env file launches the harness on a partial environment.** Same lines. `if then` as line 1: bash aborts the source at that line and continues; exit 0, harness launched (shown), stderr `…/syntax.env: line 1: syntax error near unexpected token 'then'`. Assignments after the error are not applied, so a lane meant for an alternate backend runs without `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN` (or with only some of them). Where the model id does not resolve at the default backend this degrades to A; where it does, the lane runs on a different identity, against `coachman.md:649` "One identity everywhere", and a reviewer's verdict counts as REVIEWED while the error sits in a `.err` nobody reads unless the leg is remounted. Exploit path: the user's env file. Confidence high on mechanism, medium on how often the second branch arises.

**C. P3. A prompt file of newlines passes the new check and launches an empty prompt.** `scripts/launch.sh:237` `[ -f "$PROMPT" ] && [ -r "$PROMPT" ] && [ -s "$PROMPT" ] || die "prompt file missing, unreadable or empty: $PROMPT"`, then `:238` `PTEXT=$(cat "$PROMPT")`, which strips trailing newlines. Verified: a one-newline file launches `claude -p "" --model coach-model …` with exit 0 and an empty `.err`; a whitespace-only file launches with the whitespace. Exploit path: no adversary; a prompt written from an empty variable (`printf '%s\n' "$X"`, `echo >`) by the postmaster or coachman puts a lane to work with no instruction and harvests its output as a verdict or hand-off. Confidence high.

**D. P3. A scratch left behind from an earlier round is reported as modified when it is clean.** `skills/postmaster/coachman.md:425` `git -C "$DEST" diff --name-only "$SNAP" | sed "s|^|LEFT BEHIND AND MODIFIED, $DEST: |"`, with `:500` "Any modified tracked file is a finding about the LANE". `$SNAP` is the current round's snapshot; a scratch cut for round `r`, whose removal was interrupted before round `r`'s fixes were applied, differs from `SNAP_{r+1}` by exactly the fix files. Verified in a throwaway repo: a clean detached worktree at an older commit lists `a.txt b.txt` against the newer snapshot. Exploit path: none adversarial; a coachman remounted between harvest and scratch removal, which the runbook provides for, then logs a false finding against a lane that touched nothing. Confidence high on mechanism, medium on frequency. Comparing against the scratch's own cut point (its `HEAD` when the reviewer made no commits, its reflog otherwise) removes it.
